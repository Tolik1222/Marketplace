# Marketplace (Django)

Повноцінний навчально-практичний маркетплейс на Django з каталогом товарів, кошиком, купонами, замовленнями, оплатою через Stripe та системою підтримки.

## Що реалізовано

- Реєстрація, логін, профіль користувача (`accounts`)
- Каталог товарів з категоріями, пошуком, wishlist і відгуками (`products`)
- Фільтри та сортування каталогу (ціна, наявність, тип сортування)
- Система знижок на товари + акційний блок у каталозі
- Кошик на сесіях + промокоди (`cart`)
- Оформлення замовлень (`orders`)
- Онлайн-оплата через Stripe Checkout + webhook (`payment`)
- Тікети підтримки (`support`)
- Історія замовлень у профілі користувача (`accounts`)
- Адмін-панель Django для керування даними

## Технологічний стек

- Python 3.11+
- Django 4.2.x
- Stripe API
- Cloudinary (медіа/статика)
- PostgreSQL або SQLite (через `dj-database-url`)
- Gunicorn (для деплою)

## Структура проєкту

- `config/` - налаштування Django і головні URL.
- `products/` - товари, категорії, відгуки, wishlist.
- `cart/` - логіка кошика і застосування купонів.
- `orders/` - створення замовлень і позицій.
- `payment/` - Stripe checkout та webhook.
- `accounts/` - автентифікація і профіль.
- `support/` - тікети та повідомлення підтримки.
- `templates/` - HTML-шаблони.

## Швидкий старт (локально)

1. Встановіть залежності:
   - `pip install -r requirements.txt`
2. Створіть `.env` у корені проєкту.
3. Виконайте міграції:
   - `python manage.py migrate`
4. Запустіть сервер:
   - `python manage.py runserver`

4. Блок порівняння товарів
   - Розібрався з AJAX-запитом додавання товарів до порівняння, який віддавав 404 помилку. Виправлено роутинг та обробку списку.
5. Темна тема та плавний перехід
6. Кешування за допомогою Redis
7. Експорт фінансових звітів
8. Динамічні промо-банери та актуальні категорії
   - Додано моделі `PromoBanner` та `TrendingCategory` для гнучкого керування контентом на головній сторінці з адмін-панелі Django.
   - Запроваджено ManyToMany зв'язок між актуальними категоріями та категоріями товарів.
   - Реалізовано фільтрацію за параметром `?trending_id=<id>` на бекенді, підсвічування обраної картки у шаблоні, автоматичне очищення кешу при редагуванні та збереження активної категорії у формі фільтрів.
9. Виправлення форм у кабінеті продавця
   - Переведено форми додавання та редагування товарів (`add.html` та `edit.html`) на стандартний рендеринг Django (`{{ field }}`), що відновило працездатність випадаючих списків (Select) та текстових областей (Textarea).
10. Нові інформаційні сторінки (Про нас, Гарантія, Контакти)
    - Додано три повноцінні двомовні (UA/EN) сторінки:
      - Про нас: місія, цінності та блоки статистики.
      - Гарантія: кроки звернення, інтерактивний FAQ-акордеон та терміни.
      - Контакти: інформаційні блоки, форма зв'язку та візуалізація карти.
    - Інтегровано маршрути та підключено посилання у футері сайту.





## Удосконалення

Будуть розділені на 4 фази для зручності

Фаза 1:
- Асинхронність (Celery + Redis):
- Кешування доставки 
- Оптимізація бази даних (N+1)
- Пошук Meilisearch

Тестування асинхронності:
Запустити Redis та Celery: celery -A config worker --loglevel=info
Зробити тестове замовлення. Переконатися, що сторінка успішного замовлення редиректиться миттєво, а в логах Celery з'являються записи про відправку повідомлень.
Тестування кешування Нової Пошти:
Ввести місто у полі доставки під час оформлення замовлення. Наступні подібні запити мають віддавати результат миттєво без повторного звернення до API Нової Пошти (перевірити по логах або швидкості відповіді вкладки Network).
Тестування пошуку (Meilisearch & ORM Fallback):
Перевірити роботу пошуку, коли Meilisearch вимкнений (має працювати звичайний пошук через ORM).
Запустити Meilisearch, виконати індексацію (python manage.py index_products або оновити будь-який товар) та перевірити швидкість і толерантність до помилок у пошуковому полі (наприклад, пошук "іфон" замість "iphone").
Замір кількості SQL-запитів:
Відкрити кабінет продавця (Seller Dashboard) з багатьма замовленнями і переконатися за допомогою Django Debug Toolbar або логування запитів, що кількість SQL-запитів зменшилась до константних значень (2-3 запити).




Фаза 2:

- SellerProfile — Stripe Connect + НП реквізити
- SubOrder — підзамовлення на вендора + OrderItem.sub_order
- Розділення кошика за вендорами при оформленні
- Stripe Connect Transfer — 90% виплата продавцю при оплаті
- 3 нових в'ю — деталі SubOrder, профіль, генерація ТТН
- 3 нових/оновлених шаблони — dashboard, suborder_detail, seller_profile_edit


Тест розділення кошика:
Додати в кошик товари від двох різних продавців (користувачів зі статусом staff).
Оформити замовлення. У панелі адміністратора або кабінетах обох продавців переконатися, що створено 2 окремі SubOrder із відповідними товарами.
Тест Stripe Connect:
Оплатити замовлення через Stripe Checkout. Перевірити, що статус обох підзамовлень став paid.
Генерація ТТН Нової Пошти:
В кабінеті продавця відкрити деталі підзамовлення. Натиснути кнопку "Згенерувати ТТН".
Переконатися, що підзамовлення оновилося з трек-номером Нової Пошти (або згенерованим резервним тестовим номером) та відображається правильний штрих-код.
